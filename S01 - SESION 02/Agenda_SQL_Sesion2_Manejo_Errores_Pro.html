1️⃣ TRY...CATCH Avanzado

Estructura Básica

BEGIN TRY
    -- Código que puede fallar
    INSERT INTO Tabla VALUES (...)
END TRY
BEGIN CATCH
    -- Manejo del error
    SELECT ERROR_MESSAGE() AS MensajeError;
END CATCH

Funciones de Error (Solo funcionan dentro de CATCH)

Función Descripción Ejemplo de Valor
ERROR_NUMBER() Número de error (código) 547, 2627, 1205
ERROR_MESSAGE() Mensaje descriptivo del error "Violation of PRIMARY KEY..."
ERROR_SEVERITY() Severidad del error (0-25) 16 (usuario), 20+ (fatal)
ERROR_STATE() Estado del error (contexto) 1, 2, 3...
ERROR_LINE() Línea donde ocurrió 42
ERROR_PROCEDURE() Nombre del SP/Función 'SP_Transferencia'

Severidades Importantes

Rango Tipo Acción
0-10 Informativo No es error real, solo warnings
11-16 Error de Usuario Datos inválidos, violaciones de constraint
17-19 Error de Recursos Disco lleno, límites excedidos
20-25 Error Fatal Corrupción, hardware. Desconecta sesión.
⚠️ Errores que NO captura TRY...CATCH:
  • Errores de compilación (sintaxis)
  • Errores de severidad 20+ (fatales)
  • Errores de conexión
  • Errores en deferred name resolution

Patrón Completo de Manejo de Errores

CREATE PROCEDURE SP_OperacionCritica
AS
BEGIN
    SET NOCOUNT ON;
    
    DECLARE @ErrorNumber INT, @ErrorMessage NVARCHAR(4000);
    DECLARE @ErrorSeverity INT, @ErrorState INT;
    
    BEGIN TRY
        BEGIN TRANSACTION;
            -- Operaciones críticas aquí
            UPDATE Cuentas SET Saldo = Saldo - 1000 WHERE CuentaID = 1;
            UPDATE Cuentas SET Saldo = Saldo + 1000 WHERE CuentaID = 2;
        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        -- Capturar información ANTES de cualquier otra operación
        SET @ErrorNumber = ERROR_NUMBER();
        SET @ErrorMessage = ERROR_MESSAGE();
        SET @ErrorSeverity = ERROR_SEVERITY();
        SET @ErrorState = ERROR_STATE();
        
        -- Rollback seguro
        IF @@TRANCOUNT > 0
            ROLLBACK TRANSACTION;
        
        -- Re-lanzar el error con THROW o RAISERROR
        THROW;  -- SQL Server 2012+
        -- o usar: RAISERROR(@ErrorMessage, @ErrorSeverity, @ErrorState);
    END CATCH
END

2️⃣ XACT_STATE() - El Guardián de las Transacciones

XACT_STATE() retorna el estado de la transacción actual. Es CRÍTICO para saber si puedes hacer COMMIT o ROLLBACK.

Valor Estado ¿COMMIT? ¿ROLLBACK? Situación
1 Activa (Committable) ✅ Sí ✅ Sí Todo OK, puedes decidir
0 Sin transacción ❌ No ❌ No No hay transacción abierta
-1 Doomed (Condenada) ❌ No ✅ Sí (obligatorio) Error crítico, SOLO puedes hacer ROLLBACK 
Estado de Transacción
        │
        ▼
   XACT_STATE()
        │
   ┌────┼────┐
   │    │    │
   ▼    ▼    ▼
  -1    0    1
   │    │    │
   ▼    ▼    ▼
ROLLBACK  Nada  COMMIT/ROLLBACK
(forzoso)       (tu decisión)

¿Cuándo XACT_STATE() = -1 (Doomed)?

  • Deadlock detectado
  • Error de constraint con SET XACT_ABORT ON
  • Timeout de lock
  • Error grave que invalida la transacción

Patrón Correcto con XACT_STATE()

BEGIN CATCH
    -- PRIMERO: Verificar estado de transacción
    IF XACT_STATE() = -1
    BEGIN
        -- Transacción CONDENADA: solo podemos hacer ROLLBACK
        ROLLBACK TRANSACTION;
        PRINT 'Transacción condenada - ROLLBACK forzoso';
    END
    ELSE IF XACT_STATE() = 1
    BEGIN
        -- Transacción activa: podemos elegir
        -- En errores, generalmente hacemos ROLLBACK
        ROLLBACK TRANSACTION;
        PRINT 'Transacción activa - ROLLBACK por error';
    END
    -- Si XACT_STATE() = 0, no hay transacción que manejar
    
    -- Registrar el error
    INSERT INTO LogErrores (...)
    VALUES (...);
    
    THROW;
END CATCH
💡 @@TRANCOUNT vs XACT_STATE():
  • @@TRANCOUNT: Cuenta transacciones anidadas (0, 1, 2...)
  • XACT_STATE(): Estado de la transacción (-1, 0, 1)
  • Puedes tener @@TRANCOUNT > 0 pero XACT_STATE() = -1 (transacción abierta pero condenada)

3️⃣ SET XACT_ABORT ON

Cuando está ON, cualquier error en tiempo de ejecución termina y revierte la transacción automáticamente.

Aspecto XACT_ABORT OFF (default) XACT_ABORT ON
Error de constraint Continúa ejecución Termina y ROLLBACK
Timeout Puede continuar Termina y ROLLBACK
Control Más granular "Fail Fast"
Uso recomendado SPs con manejo especial Sistemas críticos/bancarios 
CREATE PROCEDURE SP_TransaccionBancaria
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;  -- Recomendado para operaciones críticas
    
    BEGIN TRY
        BEGIN TRANSACTION;
            -- Si CUALQUIER error ocurre, todo se revierte automáticamente
            UPDATE Cuentas SET Saldo = Saldo - 5000 WHERE CuentaID = 1;
            UPDATE Cuentas SET Saldo = Saldo + 5000 WHERE CuentaID = 2;
        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        -- Con XACT_ABORT ON, XACT_STATE() será -1 en la mayoría de errores
        IF XACT_STATE() <> 0
            ROLLBACK TRANSACTION;
        THROW;
    END CATCH
END
🏦 Recomendación Bancaria:

Usar SET XACT_ABORT ON en todos los SPs que manejen dinero. Es mejor fallar rápido y revertir todo que dejar transacciones a medias.

4️⃣ Patrones de Reintento (Retry Logic)

Algunos errores son transitorios y pueden resolverse con un reintento:

Errores Transitorios Comunes

Error # Descripción ¿Reintentar?
1205 Deadlock victim ✅ Sí
1222 Lock timeout ✅ Sí
-2 Timeout de conexión ✅ Sí
8645 Memory grant timeout ✅ Sí
2627 Violación de PK ❌ No (error de datos)
547 Violación de FK ❌ No (error de datos)

Patrón de Reintento con WHILE

CREATE PROCEDURE SP_TransferenciaConReintento
    @Origen INT,
    @Destino INT,
    @Monto DECIMAL(15,2)
AS
BEGIN
    SET NOCOUNT ON;
    
    DECLARE @Intentos INT = 0;
    DECLARE @MaxIntentos INT = 3;
    DECLARE @Exito BIT = 0;
    DECLARE @ErrorNumber INT;
    
    WHILE @Intentos < @MaxIntentos AND @Exito = 0
    BEGIN
        SET @Intentos = @Intentos + 1;
        
        BEGIN TRY
            BEGIN TRANSACTION;
                UPDATE CUENTAS SET SALDO = SALDO - @Monto WHERE CUENTAID = @Origen;
                UPDATE CUENTAS SET SALDO = SALDO + @Monto WHERE CUENTAID = @Destino;
            COMMIT TRANSACTION;
            
            SET @Exito = 1;
            SELECT 'ÉXITO' AS Resultado, @Intentos AS Intentos;
        END TRY
        BEGIN CATCH
            SET @ErrorNumber = ERROR_NUMBER();
            
            IF XACT_STATE() <> 0
                ROLLBACK TRANSACTION;
            
            -- Solo reintentar si es error transitorio
            IF @ErrorNumber IN (1205, 1222, -2, 8645)
            BEGIN
                -- Esperar antes de reintentar (backoff)
                WAITFOR DELAY '00:00:01';  -- 1 segundo
                PRINT CONCAT('Reintento ', @Intentos, ' de ', @MaxIntentos);
            END
            ELSE
            BEGIN
                -- Error no transitorio: no reintentar
                SET @Intentos = @MaxIntentos;
                THROW;
            END
        END CATCH
    END
    
    IF @Exito = 0
    BEGIN
        RAISERROR('Operación fallida después de %d intentos', 16, 1, @MaxIntentos);
    END
END

Backoff Exponencial

Para evitar sobrecarga, aumentar el tiempo de espera entre reintentos:

-- Intento 1: esperar 1 segundo
-- Intento 2: esperar 2 segundos
-- Intento 3: esperar 4 segundos

DECLARE @WaitTime INT = POWER(2, @Intentos - 1);  -- 1, 2, 4 segundos
DECLARE @WaitString VARCHAR(12) = '00:00:0' + CAST(@WaitTime AS VARCHAR(2));
WAITFOR DELAY @WaitString;
⚠️ Cuidado con los Reintentos:
  • NO reintentar errores de negocio (saldo insuficiente, cuenta bloqueada)
  • Limitar número de reintentos (3-5 máximo)
  • Registrar cada reintento en el log
  • Alertar si se excede el límite de reintentos

5️⃣ Logging de Errores

Tabla de Log de Errores

CREATE TABLE LOG_ERRORES (
    LogID INT IDENTITY(1,1) PRIMARY KEY,
    FechaHora DATETIME2 DEFAULT SYSDATETIME(),
    ErrorNumber INT,
    ErrorMessage NVARCHAR(4000),
    ErrorSeverity INT,
    ErrorState INT,
    ErrorProcedure NVARCHAR(128),
    ErrorLine INT,
    Usuario NVARCHAR(128) DEFAULT SYSTEM_USER,
    HostName NVARCHAR(128) DEFAULT HOST_NAME(),
    AplicacionCliente NVARCHAR(128) DEFAULT APP_NAME()
);

SP para Registrar Errores

CREATE PROCEDURE SP_RegistrarError
AS
BEGIN
    SET NOCOUNT ON;
    
    INSERT INTO LOG_ERRORES (
        ErrorNumber, ErrorMessage, ErrorSeverity, 
        ErrorState, ErrorProcedure, ErrorLine
    )
    VALUES (
        ERROR_NUMBER(), ERROR_MESSAGE(), ERROR_SEVERITY(),
        ERROR_STATE(), ERROR_PROCEDURE(), ERROR_LINE()
    );
END

Uso en un SP

BEGIN CATCH
    -- Registrar error (esto funciona incluso con transacción condenada)
    EXEC SP_RegistrarError;
    
    -- Rollback
    IF XACT_STATE() <> 0
        ROLLBACK TRANSACTION;
    
    -- Re-lanzar error
    THROW;
END CATCH
💡 Tip: La tabla LOG_ERRORES debe tener su propio filegroup y NO estar en la misma transacción que el código que falla. Usar un SP separado garantiza que el log se guarde incluso si hay error.

6️⃣ THROW vs RAISERROR

Aspecto THROW RAISERROR
Versión SQL Server 2012+ Todas las versiones
Re-lanzar error original ✅ THROW; ❌ (necesita variables)
Severidad personalizada ❌ Siempre 16 ✅ Cualquier severidad
Requiere ; antes ✅ Sí ❌ No
Termina el batch ✅ Sí Solo si severidad 11+ 
-- THROW simple (re-lanzar error capturado)
BEGIN CATCH
    ; -- Punto y coma REQUERIDO antes de THROW
    THROW;
END CATCH

-- THROW con error personalizado
THROW 50001, 'Error personalizado del negocio', 1;

-- RAISERROR (más flexible)
RAISERROR('Error: %s', 16, 1, 'Saldo insuficiente');

-- RAISERROR con WITH LOG (registra en Windows Event Log)
RAISERROR('Error crítico en transferencia', 20, 1) WITH LOG;

📝 Resumen Ejecutivo

Concepto Qué Recordar
TRY...CATCH Captura errores de ejecución. Las funciones ERROR_* solo funcionan en CATCH.
XACT_STATE() -1 = solo ROLLBACK, 0 = sin transacción, 1 = decidir libremente
XACT_ABORT ON Fail Fast: cualquier error revierte automáticamente. Usar en sistemas bancarios.
Reintentos Solo para errores transitorios (1205, 1222). Máximo 3-5 intentos.
THROW vs RAISERROR THROW es más simple para re-lanzar. RAISERROR para control de severidad.
