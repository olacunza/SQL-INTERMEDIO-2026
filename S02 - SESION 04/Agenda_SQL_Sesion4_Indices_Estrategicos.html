🗂️ Índices Estratégicos

Diseño, implementación y mantenimiento de índices para máximo rendimiento

📊 Tipos de Índices en SQL Server
CLUSTERED
Ordena físicamente los datos. Solo 1 por tabla. Es la tabla misma.
NONCLUSTERED
Estructura separada con punteros. Hasta 999 por tabla.
COVERING
Incluye columnas extra con INCLUDE. Evita Key Lookup.
FILTERED
Índice parcial con WHERE. Más pequeño y eficiente.
⚔️ Clustered vs Nonclustered
Característica Clustered Nonclustered
Por tabla Solo 1 Hasta 999
Datos Son los datos Punteros
Orden físico Sí No

💻 Sintaxis de Índices
-- Índice básico nonclustered CREATE NONCLUSTERED INDEX IX_Tabla_Columna ON Tabla(Columna ASC); -- Índice compuesto CREATE INDEX IX_Tabla_Multi ON Tabla(Col1, Col2, Col3); -- Índice COVERING con INCLUDE CREATE INDEX IX_Tabla_Covering ON Tabla(ColBusqueda) INCLUDE (ColExtra1, ColExtra2); -- Índice FILTERED CREATE INDEX IX_Tabla_Activos ON Tabla(FechaCreacion) WHERE Estado = 'ACTIVO';
📐 Orden de Columnas en Índice
  • Primera columna = La más selectiva o más usada en WHERE
  • Columnas de igualdad primero (=)
  • Columnas de rango después (>, <, BETWEEN)
  • ORDER BY al final si aplica
  • El índice es un "libro ordenado" - solo puedes buscar desde el inicio
-- Óptimo para: WHERE A = x AND B > y ORDER BY C CREATE INDEX IX_Opt ON T(A, B, C);
📦 Cuándo usar INCLUDE
  • Columnas en SELECT que no están en WHERE
  • Columnas de JOIN adicionales
  • Columnas de GROUP BY o ORDER BY
  • NO usan espacio en páginas intermedias
  • Solo en nivel hoja del índice
-- Sin Key Lookup para: SELECT Nombre, Email WHERE Fecha = x CREATE INDEX IX_Fechas ON Clientes(Fecha) INCLUDE (Nombre, Email);
🎯 Índices Filtrados

Índice que solo incluye filas que cumplen una condición. Ideal para columnas con valores muy desiguales.

  • Más pequeños = Menos espacio y mantenimiento
  • Más eficientes = Menos páginas por recorrer
  • Ejemplos: Estado='ACTIVO', Fecha > '2024-01-01'
  • La query debe coincidir con el filtro
🔧 Mantenimiento de Índices
  • Fragmentación < 10%: No hacer nada
  • Fragmentación 10-30%: REORGANIZE
  • Fragmentación > 30%: REBUILD
  • REORGANIZE: Online, menos recursos
  • REBUILD: Offline por defecto, más efectivo
ALTER INDEX IX_Nombre ON Tabla REORGANIZE; ALTER INDEX IX_Nombre ON Tabla REBUILD; ALTER INDEX ALL ON Tabla REBUILD;
✅ Mejores Prácticas
✓ Analizar antes de crear
Usar planes de ejecución y missing index hints antes de crear índices
✓ Columnas estrechas
Preferir INT sobre BIGINT, DATE sobre DATETIME cuando sea posible
✓ INCLUDE vs KEY
Usar INCLUDE para columnas que solo se leen, no se buscan
⚠️ Balance lectura/escritura
Cada índice ralentiza INSERT/UPDATE/DELETE
⚠️ Revisar uso
Índices no usados consumen espacio y tiempo de mantenimiento
✗ Evitar duplicados
No crear índices que ya están cubiertos por otros
