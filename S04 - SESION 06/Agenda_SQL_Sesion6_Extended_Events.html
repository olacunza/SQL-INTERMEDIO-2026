🆚 SQL Profiler vs Extended Events

❌ SQL Profiler (Deprecated)

  • Overhead alto (5-10%)
  • No soportado en Azure SQL
  • Filtros limitados
  • Un solo destino de salida
  • Interfaz separada

✅ Extended Events (Recomendado)

  • Overhead mínimo (<1%)
  • Soportado en Azure SQL
  • Filtros muy flexibles (predicados)
  • Múltiples targets simultáneos
  • Integrado en SSMS
💡 Recomendación Microsoft: Extended Events es el sistema de monitoreo estándar desde SQL Server 2008. SQL Profiler está marcado como DEPRECATED y será removido en futuras versiones.

📦 Targets (Destinos)

🔄 ring_buffer

Memoria circular (volátil)

  • Datos en RAM (se pierden al reiniciar)
  • Ideal para diagnóstico rápido
  • Lectura inmediata con XQuery
  • Tamaño limitado (MD típico: 4-8 MB)
ADD TARGET package0.ring_buffer (SET max_memory = 4096)

📁 event_file

Archivo .xel en disco (persistente)

  • Datos persistentes en archivos .xel
  • Ideal para histórico y auditoría
  • Soporta rollover automático
  • Lectura con fn_xe_file_target_read_file
ADD TARGET package0.event_file (SET filename = N'C:\Temp\Mi.xel')
⚡ Tip: En producción, usa ambos targets: ring_buffer para consultas rápidas "¿qué está pasando ahora?" y event_file para histórico y análisis posterior.

🛠️ Sintaxis Básica

-- CREAR SESIÓN
CREATE EVENT SESSION MonitorBancoDB
ON SERVER
ADD EVENT sqlserver.sql_statement_completed (
    ACTION (
        sqlserver.sql_text,
        sqlserver.database_name,
        sqlserver.username
    )
    WHERE duration > 1000000              -- > 1 segundo (microsegundos)
      AND sqlserver.database_name = N'BancoDB'
)
ADD TARGET package0.ring_buffer (SET max_memory = 4096)
ADD TARGET package0.event_file (
    SET filename = N'C:\Temp\BancoDB.xel',
        max_file_size = 50,               -- 50 MB por archivo
        max_rollover_files = 5            -- Máximo 5 archivos
)
WITH (
    MAX_MEMORY = 4096 KB,
    EVENT_RETENTION_MODE = ALLOW_SINGLE_EVENT_LOSS,
    MAX_DISPATCH_LATENCY = 5 SECONDS,
    STARTUP_STATE = ON                    -- Iniciar con SQL Server
);

-- INICIAR/DETENER
ALTER EVENT SESSION MonitorBancoDB ON SERVER STATE = START;
ALTER EVENT SESSION MonitorBancoDB ON SERVER STATE = STOP;

-- ELIMINAR
DROP EVENT SESSION MonitorBancoDB ON SERVER;

🔍 Leer Datos Capturados

Desde ring_buffer (XQuery):

;WITH XEventData AS (
    SELECT CAST(target_data AS XML) AS TargetData
    FROM sys.dm_xe_session_targets st
    INNER JOIN sys.dm_xe_sessions s 
        ON s.address = st.event_session_address
    WHERE s.name = 'MonitorBancoDB'
      AND st.target_name = 'ring_buffer'
)
SELECT 
    e.value('(@timestamp)[1]', 'datetime2') AS FechaHora,
    e.value('(data[@name="duration"]/value)[1]', 'bigint') / 1000 AS DuracionMS,
    e.value('(action[@name="sql_text"]/value)[1]', 'nvarchar(max)') AS SQL_Text
FROM XEventData
CROSS APPLY TargetData.nodes('RingBufferTarget/event') AS x(e)
ORDER BY FechaHora DESC;

Desde archivo .xel:

SELECT 
    event_data.value('(@timestamp)[1]', 'datetime2') AS FechaHora,
    event_data.value('(data[@name="duration"]/value)[1]', 'bigint') / 1000 AS DurMS
FROM sys.fn_xe_file_target_read_file(
    'C:\Temp\BancoDB*.xel', NULL, NULL, NULL
) AS f
CROSS APPLY (SELECT CAST(event_data AS XML)) AS x(event_data);

🏦 Aplicación Bancaria: Sesión de Producción

Escenario: Diseñar una sesión integral para el Core Bancario que capture:

  • ✅ Consultas lentas (> 5 segundos)
  • ✅ Todos los Deadlocks (grafo XML completo)
  • ✅ Errores críticos (severity >= 16)
  • ✅ Logins fallidos (para auditoría)

Configuración recomendada:

  • EVENT_RETENTION_MODE = NO_EVENT_LOSS para deadlocks
  • STARTUP_STATE = ON para que inicie automáticamente
  • Ring buffer de 8 MB + Event file de 500 MB (10 archivos x 50 MB)

⚠️ Unidades de Tiempo

¡IMPORTANTE! La duración en Extended Events está en MICROSEGUNDOS, no milisegundos:

  • 1 segundo = 1,000,000 microsegundos
  • 500 ms = 500,000 microsegundos
  • 100 ms = 100,000 microsegundos

Para convertir: duration / 1000 = milisegundos
